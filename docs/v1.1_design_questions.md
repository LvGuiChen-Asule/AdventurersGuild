# V1.1 Design Questions（设计问题登记）

> 按 §47：发现"这样设计更好"时记录于此，不擅自修改主线结构/NPC/章节/事件/Lore/Endgame 等既定设计。

## QUESTION-001：EXPLORE 群系匹配方式

QUESTION: EXPLORE 任务当前用生物群系 ID 精确匹配（`minecraft:plains` 等）。

CURRENT DESIGN: `playerInBiome()` 使用 `Registry<Biome>.getKey(biome.value()).equals(target)` 精确匹配。

PROPOSED CHANGE: 支持生物群系标签（如 `#minecraft:is_overworld`）或前缀匹配，提升自定义群系/数据包兼容性。

REASON: 精确 key 匹配在装有自定义群系 Mod 或数据包改动时可能失效；标签更稳健。

IMPACT: Quest JSON 的 objective.target 语义扩展（`#` 前缀表示标签）；EXPLORE 判定函数与文档更新；对既有任务 JSON 无破坏（不填 `#` 时仍走精确匹配）。

## QUESTION-002：TRANSPORT 送达目标

QUESTION: TRANSPORT 任务当前固定送达主世界出生点（extra="spawn"）。

CURRENT DESIGN: `deliveryTarget()` 对 "spawn" 返回 `level.getSharedSpawnPos()`。

PROPOSED CHANGE: TASK-005 公会自然生成后，新增 extra="guild" 送达目标（公会坐标，来自 GuildWorldData），默认送达点改为公会。

REASON: 公会成为世界中心后，把物资"运回公会"比"运回出生点"更符合 V1.1 定位与叙事。

IMPACT: 需要 GuildWorldData 提供 guildX/Y/Z；既有 "spawn" 任务保留；新增 "guild" 关键字与对应任务 JSON；UI 文案更新。

## QUESTION-003：公会建筑生成方式（已实施）

QUESTION: Jigsaw 的 `project_start_to_heightmap` 对本项目单块 rigid 模板无效，实测每次都在 Y=0 地下生成。

CURRENT DESIGN（原）: Structure + StructureSet + random_spread + jigsaw 高度投影。

PROPOSED CHANGE（已实施）: 主公会改为**确定性手动放置**：出生点附近 400 格内寻找合规地表（允许生物群系 + 非海洋），用 StructureTemplate.placeInWorld 铺到地表高度，真实原点写入 GuildWorldData；structure_set 移除（杜绝地下空壳），structure JSON/模板/生物群系 tag 保留作为框架与定位依据。

REASON: 稳定性与玩家体验优先（§48 优先级 1/2）；jigsaw 高度投影在无 jigsaw 扩展链时不可靠。

IMPACT: 每世界恰好一个公会、必然在地表、NPC 站位可用固定偏移（Rotation.NONE）；`/ag guild locate` 直接读 GuildWorldData；新增世界即可验证。
