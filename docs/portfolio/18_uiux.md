# 18 UI/UX 策划

## WHY：为什么 UI 值得单独成章？

任务系统再完整，玩家每天面对的是**界面**。V1.0 的 6 个界面是功能导向的
（能开、能点、能看），但存在信息密度高、层级弱、反馈不足的问题。
V1.1 用"深木 / 羊皮纸 / 暗金 / 深蓝"主题统一全部 10 个页面，目标是：

- 一眼认出"这是冒险者公会的界面"，而不是"又一个 MC 菜单"；
- 品质/锁定/状态用颜色与图标两级编码（不依赖单一通道）；
- 高频操作（接任务、刷新、购买）恒定位置，形成肌肉记忆。

## 关键交互设计决策

### 1. 品质 = 颜色 + 文本双重编码

任务标题用品质色渲染（白/绿/蓝/紫/橙），同时行内显示中文品质名——
保证色盲玩家与截图读者都能识别稀有度。

### 2. 锁定 = 明示原因

锁定任务不隐藏，而是显示"需要 Lv.x / 需要声望 x / 章节未解锁"，
把"我不能接"变成"我该去做什么"（目标引导而非挫败）。

### 3. 未注册 = 全屏 CTA

任务大厅未注册时只显示注册按钮 + 一行文案，不做多入口分流，
保证新手第一次进大厅只做一件事：注册。

### 4. 刷新成本可视化

刷新按钮直接显示"刷新任务 (50G)"，把"要不要花钱重抽"的决策成本前置到按钮本身。

### 5. 快捷键 G/J/K/L

公会总览 / 任务大厅 / 冒险者信息 / 档案，全部可重绑（KeyMapping）；
高频界面不强制玩家先找到 NPC 或方块。

## 现状与改进点（诚实评估）

| 现状 | 问题 | V1.2 计划 |
| --- | --- | --- |
| 默认 MC 字体渲染 | 中英文混排行高/截断风险 | 自定义位图字体 + 行高测试 |
| 264 固定窗口 | 小屏可用，大屏浪费 | 支持 1.25/1.5 倍缩放 |
| 文本一次性 drawWordWrap | 长文本遮挡 | 打字机效果 + 分页 |
| 无动画/音效 | 反馈弱 | 按钮悬停音、奖励闪光 |
| 状态反馈靠聊天栏 | 重要事件（升级/解锁）感知不足 | 屏幕中央 Toast 通知 |

## IMPLEMENT：怎么落地？

- `client/AbstractGuildScreen`：共享尺寸/颜色/导航/滚动/格式化；
- `client/screen/*`：10 个页面各自实现 `rebuildWidgets` + `render`；
- `client/ClientGuildData`：客户端数据快照，收到 S2C 包即刷新当前页；
- `network/OpenGuildScreenPacket`：服务端控制"打开哪个界面"（NPC 对话入口）。

## VALUE：体现什么策划能力？

- **UX 思维**：把"锁定原因""刷新成本""未注册 CTA"做成显性信息，减少玩家困惑；
- **视觉规范**：一套色板 + 基类复用 = 10 页视觉一致性（低成本高收益）；
- **可测试性**：所有状态（锁定/空/未注册）都有明确占位文案，截图与回归测试可预期；
- **工程协作**：UI 与网络快照解耦——客户端只渲染"服务端给的数据"，改数据不改 UI。
