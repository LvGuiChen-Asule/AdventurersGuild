# 27 项目复盘

> 本节要求真实。不写"项目取得了巨大成功"，只写事实、失败与教训。

## 我为什么设计这个 Mod？

玩 MC 久了会发现一个矛盾：**世界无比自由，但自由到没有目标**。
原版有进度（进度系统、进度成就），却没有"任务"——没有 NPC 派活、没有"世界因为你做了事而改变"。

我想验证一个假设：**不改变 MC 任何核心玩法，只给既有行为加目标、奖励与叙事反馈，
能否让玩家的冒险有方向感？** 这就是 Adventurer's Guild 的起点。

## 它解决什么问题？

- 给"进入下界/找到要塞/杀龙"这些原版行为一个**承认**（事件 + 档案 + 对话）；
- 给"不知道接下来干嘛"一个**方向**（每日板 + 任务链 + 章节）；
- 给"组队玩没有共同身份"一个**容器**（冒险团）。

## 最大的设计难点：弱线性

主线最容易的做法是"锁任务"：不完成 A 就不能接 B。但 MC 玩家最恨被锁，
而且原版流程玩家可能**提前杀龙**。硬锁会直接毁掉 Mod 的信任。

难点在于：**怎么做到"有主线"又"不锁玩家"？**

解法（V1.1 已实现）：

1. 所有关键行为先落成**世界事件**（once=true），系统只记录"你做过了"；
2. 章节解锁 = 事件判定（进下界解锁第二章，杀龙解锁 Endgame）；
3. 里程碑任务接取时若事件已存在 → **自动完成**；
4. 前置判定放宽容：上一任务已**完成**或**对应事件已记录**，都放行。

结果：提前杀龙的玩家回到公会，发现系统"早就知道"，任务补发而不是惩罚。

## 失败过的设计（按时间线）

### 1. Jigsaw 结构生成 → 公会建在地下 Y=0

V1.1 初期用标准 Jigsaw Structure 生成，实测多次都是地下空壳。
根因：单体模板的高度投影机制对 45×35 大模板不可靠。
**教训：MC 世界生成机制要"先冒烟后依赖"，不能按文档假设。**
最终方案：放弃 Jigsaw 放置，改地表手动放置 + 坐标入 SavedData（Jigsaw 仅保留框架）。

### 2. 橡木门生成成掉落物

模板里放门，放置时地形/方块状态冲突，门直接以物品形式掉在地上（用户实测反馈）。
**教训：涉及有状态方块（门/床/活塞）时，模板放置后必须手动校验/重写状态。**
最终：模板放置后单独写入完整双开门方块状态。

### 3. NPC 用固定偏移 → 模板一改全乱

第一次按"模板原点+固定偏移"生成 NPC，用户改模板后 NPC 出现在房顶。
**教训：固定偏移是脆弱契约，人和建筑的关系应由"标记物"决定。**
最终：地毯标记扫描（按角色颜色地毯定位，旋转/高度安全）+ 固定偏移兜底。

### 4. 地形穿模

建筑生成时没清地形，树和山体插进大厅。
**教训：世界生成必须连"地皮"一起设计，不是只放一个壳。**
最终：清空建筑脚印内方块 + 周边 4 格土台（用户要求的"留几格空档"）。

### 5. 每日任务池与任务链共用任务

同一个任务可能同一天既在每日板又在任务链里出现（UI 已去重，接受校验允许其一）。
**教训：内容池去重要在设计层做，而不是 UI 层补。**
V1.2 计划：任务池按"来源标签"隔离（board/chain）从源头排除。

### 6. 声望没有消耗渠道

V1.0 声望只累积、只解锁，金币有商店/刷新回收，声望零回收。
**教训：任何"货币"都要回答"能花在哪"；V1.2 计划加声望商品与服务。**

## 如果重新开始，我会怎么设计？

1. **第一天就 `git init`**：本项目至今无版本库（技术债第一名）；
2. **先写自动化测试**：NBT 序列化、任务状态机、经济边界，至少 10 个核心用例；
3. **先验证世界生成再写其他**：结构高度/地形清理这种"地基问题"应最先冒烟，
   而不是等全部功能做完再被用户实测打回来；
4. **数值先埋点**：完成率/刷新率/升级天数这些指标应该 V1.0 就埋，而不是 V1.1 补；
5. **内容先少而深**：80 个任务比 32 个强，但 32 个打磨过的任务 > 80 个未验证的任务。

## 做得对的地方（克制地说）

- "服务端权威 + 数据驱动 + 事件驱动"三条原则从 V0.1 坚持到 V1.1，没有推倒重来；
- 弱线性用事件记录实现，被真实玩家提前杀龙场景验证有效；
- 每次用户实测反馈（地下、门掉落、NPC 房顶、穿模）都形成修复记录，而不是"打补丁就跑"；
- 诚实标注"已实现待验证"，不把 README 当事实。

## VALUE：体现什么策划能力？

- **复盘能力**：能区分"设计失败"（弱线性难点）与"工程失败"（Y=0/门掉落）并分别归因；
- **迭代思维**：每个失败都有"教训 → 方案 → 落地"的完整闭环；
- **用户反馈闭环**：6 条真实用户反馈全部转化为代码修改并记录；
- **谦逊与可信度**：承认无 git、无测试、声望无消耗，招聘方看到的是一份真实项目。
