# 25 Demo 演示流程（10–15 分钟）

## WHY：为什么需要一个标准 Demo？

作品集面试时，面试官只有 10–15 分钟。Demo 必须把"最像游戏"的闭环压缩进去：
**玩家行为 → 系统反馈 → 世界变化**。每一步都要能说出"这里在展示什么能力"。

## 流程（16 步，约 13 分钟）

| # | 步骤 | 操作 | 系统反馈（录制要点） | 展示能力 | 时长 |
| --- | --- | --- | --- | --- | --- |
| 01 | 创建世界 | 新建世界并进入 | 公会大厅自动出现在出生点附近地表 | 世界生成/建筑落地 | 1m |
| 02 | 找到公会 | 顺着出生点方向走 | 聊天提示"你发现了冒险者公会 + 坐标"；事件"发现公会"入档 | 世界事件/弱引导 | 1m |
| 03 | 进入公会 | 打开橡木门 | 大厅实景：柜台/任务墙/萤石/分区 | 空间设计 | 30s |
| 04 | 与艾琳交互 | 右键接待员 | 对话界面打开，选择"注册冒险者" | NPC 实体+对话系统 | 1m |
| 05 | 注册 | 对话动作 | 冒险者档案建立；Lore"旧时代冒险者"入档 | 对话动作/成长档案 | 30s |
| 06 | 接取任务 | 右键罗德→任务大厅 | 每日板 6 任务（3 普/2 优/1 稀）品质色区分 | 每日任务/品质 | 1m |

| 09 | 进下界 | 搭下界门进入 | 事件"踏入下界"+Lore"关于下界"+第二章解锁 | 事件驱动/弱线性 | 1m |

| 16 | 展示冒险团 | /ag party create | 团队创建+信息界面 | 多人前瞻 | 30s |

## 脚本要点

1. **两条叙事线并行**：观众看到的是一条完整冒险（找公会→注册→做任务→下界→末地→杀龙→Endgame），
   策划口中讲的是"为什么这样设计"；
2. **每次系统反馈都要念"反馈链"**：行为 → 事件 → 档案/对话/章节，三件套必说；
3. **准备两个存档**：主存档做实时流程（步骤 1–11），
   备用"龙已击杀"存档展示 Endgame（步骤 12–16），避免 Demo 卡在找要塞；
4. **出问题不慌**：所有系统有命令兜底（/ag complete、/ag debug event、/ag debug reset），
   提前在脚本上标注每个步骤的兜底命令。

## 兜底命令速查（开发/演示用）

| 场景 | 命令 |
| --- | --- |
| 快速完成当前任务 | `/ag complete <quest_id>` |
| 记录事件 | `/ag debug event <EVENT_ID>` |
| 解锁章节 | `/ag debug chapter <chapter_id>` |
| 查公会坐标 | `/ag guild locate` |
| 重置演示状态 | `/ag debug reset`（OP2） |

## VALUE：体现什么策划能力？

- **演示设计**：把 200+ 项功能压缩成 13 分钟叙事，每步有"展示能力"标签；
- **风险预案**：演示脚本带兜底命令，体现职业素养；
- **叙事节奏**：30s–2m 的步长设计符合面试注意力曲线。
