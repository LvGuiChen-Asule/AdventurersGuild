# 02 核心设计理念

## 一句话理念

> **"玩家做了什么，世界就对此做出回应。"**

Adventurer's Guild 不是"接任务 → 拿金币"的流水线，而是一套**行为识别 + 目标赋予 + 世界反馈**的系统。

## 原版痛点 → Mod 回答

| 原版痛点 | Mod 回答 |
| --- | --- |
| 目标自由度极高，缺少持续驱动 | 任务墙每天刷新，给原版行为配目标 |
| 世界不记得玩家做过什么 | Chronicle / 世界事件 / NPC 对话反馈 |
| 成长缺少"可见的资历" | 等级称号 + 公会声望阶段 |
| 下界/末地缺乏叙事意义 | 主线章节把"去下界/打龙"变成里程碑 |
| 击败末影龙即"通关" | Endgame 24 目标，龙后冒险继续 |

## 三大支柱

1. **数据驱动**：内容（任务/商店/装备/对话/事件/Lore）全部 JSON，配表 Excel 同步；换内容不换代码。
2. **服务器权威**：客户端只显示与请求；状态、奖励、解锁全部服务端判定（防作弊、防重复奖励）。
3. **弱线性主线**：不限制玩家提前进下界/末地/打龙，系统**识别已发生的行为**并自动推进。

## 为什么"主线负责意义、支线负责资源"

- 主线：世界探索、章节推进、解锁、事件、Lore → 给玩家"为什么要继续"的理由
- 支线：Gold/EXP/Reputation/资源/装备 → 给玩家"靠什么变强"的途径

二者职责分离，避免"主线像刷钱机"或"支线抢剧情"。

## 设计检查清单（每个系统都回答）

WHY 为什么存在？WHAT 是什么？HOW 怎么玩？DATA 怎么量化？IMPLEMENT 怎么落地？VALUE 体现什么能力？

## 差异化论证：为什么需要"冒险者公会"？

原版玩家需要的是一个**常驻的、有记忆的、会成长的枢纽**：

- 提供目标（任务墙）
- 提供资历（等级/声望/档案）
- 提供交易（商店）
- 提供反馈（NPC 知道你去过下界、打过龙）
- 提供归宿（公会建筑是真实世界的一部分）

公会 = "把散落在原版世界里的行为串成一条成长线"的叙事与系统锚点。
