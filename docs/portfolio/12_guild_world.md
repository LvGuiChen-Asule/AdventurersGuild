# 12 公会建筑与世界生成

## WHY：为什么公会必须是"真实建筑"？

这是本项目与纯 GUI 类任务 Mod 的分水岭决定：

- 玩家需要在世界里有一个**看得见、进得去、认得出**的"家"；
- 任务、商店、档案、远征这些功能必须对应到建筑里的**空间位置**，玩家才会形成空间记忆
  （"柜台后面是艾琳，右手边是任务墙，最里面是档案室"）；
- 自然生成让每个世界都有一个唯一的公会坐标，`/ag guild locate` 才有意义。

## WHAT：公会建筑（V1.1 已实现）

### 建筑规格

| 项 | 值 |
| --- | --- |
| 模板 | `structures/guild_hall.nbt`（Structure Template） |
| 尺寸 | 45 × 20 × 35（长×高×宽），占地约 45×35 格 |
| 生成方式 | 出生点附近地表确定性放置（手动放置，见下） |
| 地形处理 | 建筑脚印内清空 + 周边 4 格土台整平（留空档） |
| 入口 | 南墙 (22,1,34) 双开橡木门（模板放置后单独写入，防掉落物） |
| 采光 | 建筑内放置萤石防刷怪 |
| 材质 | 石英柜台/办公区 + 原版橡木结构（按用户模板要求） |
| 坐标记录 | GuildWorldData（SavedData）：`guildX/guildY/guildZ + guildDimension` |

玩家动线设计：

1. 进门先看到**柜台与艾琳**（注册入口），完成"我是谁"；
2. 右手边**任务墙与罗德**（接任务），完成"我做什么"；
3. 柜台旁**米娅**（买补给），完成"我拿什么出发"；
4. 深入后区：**格雷**（下界/末地路线）、**伊莱恩**（档案/历史）、**塞拉斯**（终末研究）；
5. 动线由"事务频率"决定：注册/接任务/购物高频放前厅，剧情/档案低频放后区。

## HOW：世界怎么生成公会？（V1.1 已实现）

### 生成规则

```
玩家登录主世界
  → 检查 GuildWorldData.isGuildGenerated()
  → 未生成：
      1. 出生点 96 格半径、8 格步进搜索地表
      2. 优先"平原/森林"标签群系，其次任意陆地，最后出生点兜底
      3. 记录地表高度（WORLD_SURFACE_WG，且高于海平面）
      4. 清空 45×35 脚印内地形 + 周边 4 格土台
      5. 放置 guild_hall.nbt → 补放入口门 → 记录坐标
      6. 触发 EVENT_GUILD_FOUND（世界级 + 玩家级）
  → 已生成：直接读取坐标，不重复放置
```

### 迭代修复记录（真实开发过程，体现工程能力）

| 问题 | 根因 | 解决（V1.1） |
| --- | --- | --- |
| 公会生成在地下 Y=0 | Jigsaw 高度投影对单体模板不可靠 | 改为地表手动放置，坐标入 SavedData；Jigsaw 仅保留框架、移除 structure set，杜绝地下空壳 |
| 橡木门以掉落物形式出现 | 模板内门与地形/方块状态冲突 | 模板放置后单独写入完整双开门方块状态（朝向/铰链/上下半块） |
| 建筑内树/山体穿模 | 未清理地形 | 清空脚印内方块 + 周边 4 格土台，四周留空档 |
| NPC 生成位置错乱/在房顶 | 固定偏移依赖模板原点，模板改动即错位 | 扫描地毯标记定位站位（旋转/高度安全），记录 NPC 家坐标 |
| 多次生成重复 NPC | 无生成标记 | `npcsSpawned` 标志写入 SavedData，保证每世界一次 |

## DATA：世界数据

GuildWorldData（SavedData，`adventurersguild_world`）保存：

- `guildGenerated / guildX/Y/Z / guildDimension / guildLevel`：公会位置与等级（等级为 V1.2 预留字段）；
- `npcsSpawned`：NPC 生成标记；
- `worldEvents / globalLore`：世界级事件与全局档案；
- `parties`：冒险团注册表。

## IMPLEMENT：怎么落地？

- `world/GuildWorldEvents`：登录事件 → 放置；`findPlacementPos` 搜索地表；`clearTerrain` 清地形；`placeDoor` 补门；
- `guild/GuildWorldData`：SavedData 持久化；
- `npc/GuildNpcManager`：地毯扫描 + 固定偏移兜底，每世界一次生成；
- 指令：`/ag guild locate` 查询坐标；`/ag debug guild` 查状态；`/ag debug reset` 重放（开发用）。

## VALUE：体现什么策划能力？

- **关卡/空间策划**：功能分区按"事务频率"排布，动线最短；
- **数值之外的体验设计**：建筑即教程（进门=注册，任务墙=接任务）；
- **跨程序沟通**：把策划需求翻译成 NBT 模板 + 放置算法 + 地形清理；
- **真实落地与复盘**：Y=0、门掉落、NPC 房顶、地形穿模四个真实 bug 全部记录修复过程，
  证明不是"纸面策划"，而是能扛住真实测试反馈的策划。
